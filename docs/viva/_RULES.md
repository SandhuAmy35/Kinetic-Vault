DOCUMENTATION RULES
1. Audience: a student who did not write this code and must explain it to an examiner in a viva. Plain English first, code detail second. Define every technical term the first time it appears in a document.
2. Accuracy: read the real source before writing about it. Never invent files, classes, methods or behaviour. Refer to code by file path and method name, not line numbers. If something is unclear, write UNCLEAR and quote the code. End each document with a list titled Covers these files.
3. For every class: its purpose in one sentence, who creates or calls it, key fields, and for each non-trivial method: what it does in plain words, parameters, return value, what calls it, what it calls, and edge cases or failure handling.
4. Explain every non-basic Java or Android construct the first time it appears in a document, with a tiny real example from this code (max 10 lines). Non-basic means anything beyond plain variables, if/for/while, simple methods and fields. Always include: lambdas and callbacks, interfaces, anonymous and inner classes, generics, try-with-resources, bitwise operators and shifts, byte/char/int conversions, ExecutorService and threads, Handler and Looper, lifecycle methods, Intents, Uri and ContentResolver, the Activity Result API, BroadcastReceiver, Canvas, Paint and ValueAnimator, SQLite classes, HttpURLConnection and JSON, and every javax.crypto, java.security and java.util.zip class used.
5. For every algorithm (key derivation, encryption, bit embedding, Ghost shuffle, complementary filter, gesture detection, PSNR): the idea in plain English, a tiny worked example with real numbers, then a step-by-step code walkthrough, then the exact constants used and why.
6. For every feature: what the user sees, the full call chain as an ASCII flow (Screen -> Class.method -> Class.method), where data is stored, what happens on failure, and security notes.
7. End every document with 5 likely viva questions and short answers.
8. Skimmable: headings, short paragraphs, tables for file lists, no marketing language.
9. Edit nothing outside docs/viva/. Reply in 3 lines. Write files to disk, never print them in chat.
